# 咖啡渣管理系统项目需求文档
## 1. 项目概述

### 1.1 项目名称

Coffee Grounds Keeper

### 1.2 项目简介

Coffee Grounds Keeper 是一个基于 Linux 开发板的咖啡渣管理系统。项目可以将咖啡渣干燥后变为吸附剂或将咖啡渣加水发酵后变为废料。
系统还包含显示屏模块，用于显示当前管理区的咖啡渣温湿度，并可播放咖啡制作或咖啡渣处理相关教程视频。

### 1.3 项目目标

* 实现咖啡渣状态检测
* 实现温湿度数据显示
* 实现显示屏视频播放功能
* 为后续扩展风扇、水泵、电机、舵机等执行器控制预留接口

---

## 2. 使用场景

### 2.1 场景一：咖啡渣干燥处理

用户选择干燥模式。系统根据用户设置选择将咖啡渣自然风干或系统风干为吸附剂。

### 2.2 场景二：咖啡渣发酵处理

用户选择发酵模式，系统检测咖啡渣湿度状态，并提示是否需要加水。处理后的咖啡渣可作为花盆肥料使用。

### 2.3 场景三：信息展示

系统通过显示屏显示温度、湿度、处理建议，并可播放咖啡制作或咖啡渣再利用视频。

## 4. 非功能需求

### 4.1 性能需求

* 温湿度数据每整点刷新一次
* 显示界面应能在数据更新后及时刷新
* 视频播放时不应影响基本传感器读取功能

### 4.2 稳定性需求

* 程序异常退出后应能重新启动
* 传感器读取失败时，系统不应崩溃
* 配置文件缺失或格式错误时，系统应给出明确提示

### 4.3 可维护性需求

* 硬件接口代码应与业务逻辑分离
* GPIO、I2C 地址、阈值等参数应放在配置文件中
* 项目应保留清晰的模块划分，便于后续扩展

### 4.4 可扩展性需求

* 后续应能方便增加新的传感器
* 后续应能方便增加新的执行器
* 后续应能扩展 Web 控制界面或触摸屏界面

## 7. 系统状态设计

系统可包含以下状态：

| 状态         | 说明        |
| ---------- | --------- |
| IDLE       | 待机状态      |
| CHECKING   | 正在检测咖啡渣状态 |
| DRYING     | 干燥处理模式    |
| FERMENTING | 发酵处理模式    |
| READY      | 处理完成      |
| ERROR      | 异常状态      |

### 7.1 状态转换示例

```text
IDLE
  ↓
CHECKING
  ↓
DRYING / FERMENTING
  ↓
READY
```

如果传感器异常或设备故障，则进入：

```text
ERROR
```

## 8. 配置需求

系统应支持通过配置文件设置以下参数：

```yaml
sensor:
  temp_humidity:
    type: sht30
    bus: i2c
    address: 0x44

threshold:
  dry_humidity: 20
  ferment_humidity: 60
  max_temperature: 45

display:
  video_path: ./media/videos/
  refresh_interval_ms: 1000

actuator:
  fan_gpio: 17
  pump_gpio: 27
  motor_pwm: 0
```
